02 · RL-loopen

To funksjoner og én løkke

Notatene · avsnitt 4.3 · s. 58 (signaturene); løkkene er forslag

Gym-APIet trenger bare to funksjoner for å lage RL-loopen: én som setter environmentet i starttilstanden, og én som tar en action.

env.reset()        → Tuple[initial_state, info]
env.step(action)   → Tuple[state, reward, done, info]

Først settes environmentet i starttilstanden. Deretter enten en for-loop som itererer over maks antall steg og terminerer når maks er nådd eller done == True, eller en while-loop som terminerer når done == True. I loopen sender agenten inn actions, mottar ny state og reward, og velger nye actions.

state, info = env.reset()                                   # episoden starter
for t in range(max_steps):                                  # for-loop: stopper også ved maks antall steg
    action = agent.choose_action(state)                     # policy: ε-greedy på Q
    new_state, reward, done, info = env.step(action)        # miljøet svarer
    agent.learn(state, action, reward, new_state, done)     # Bellman-oppdatering, hvert trekk
    state = new_state
    if done:
        break
state, info = env.reset()
done = False
while not done:                                             # while-loop: stopper bare på done
    action = agent.choose_action(state)
    new_state, reward, done, info = env.step(action)
    agent.learn(state, action, reward, new_state, done)
    state = new_state

Tre-på-rad har to spillere, så loopen må velge hvem som trekker. Med to agenter som lærer hver sin tag, og ε som minkes én gang per spill:

env = TicTacToe()
agent_x, agent_o = Player('X'), Player('O')

for game in range(n_games):                                 # én episode = ett parti
    state, _ = env.reset()
    done = False
    while not done:
        player = agent_x if env.player_turn == 'X' else agent_o
        action = player.choose_action(state)
        new_state, reward, done, _ = env.step(action)
        player.learn(state, action, reward, new_state, done)
        state = new_state
    agent_x.update_exp_factor()                             # epsilon decay per spill
    agent_o.update_exp_factor()

Her lærer bare spilleren som trakk. Skal taperen også lære av at motstanderen vant (negativ reward for sitt forrige trekk), må loopen huske forrige state og action for hver spiller og kalle learn for begge når done blir sann; det er en vanlig utvidelse i øvingen.

03 · Environment

Tre-på-rad som klasse

Notatene · avsnitt 4.3 · s. 58 (funksjonslista); koden er forslag

Et environment må ha en tilstand, ta imot en action, gå over i en ny tilstand og returnere reward. Staten er strengen 012345678 der sifre er ledige ruter. Fem funksjoner: __init__, reset, step, check_winner og (valgfritt) render.

class TicTacToe:
    def __init__(self):
        self.initial_state = '012345678'                    # tomt brett
        self.state = self.initial_state
        self.winner = None
        self.player_turn = 'X'                              # X begynner
        self.wins = {'X': 0, 'O': 0, 'draw': 0}              # tellere, nyttig under trening

    def reset(self):                                        # tilbake til start, returnerer initial state
        self.state = self.initial_state
        self.winner = None
        self.player_turn = 'X'
        return self.state, {}

    def step(self, action):                                 # action = indeks til en ledig rute
        self.state = self.state[:action] + self.player_turn + self.state[action + 1:]
        if self.check_winner():                             # tre på rad → spilleren som trakk vinner
            self.winner = self.player_turn
            self.wins[self.winner] += 1
            return self.state, 1, True, {'winner': self.winner}
        if not any(s.isnumeric() for s in self.state):      # fullt brett → uavgjort, reward 0
            self.wins['draw'] += 1
            return self.state, 0, True, {'winner': None}
        self.player_turn = 'O' if self.player_turn == 'X' else 'X'   # bytt tur
        return self.state, 0, False, {}                     # ikke over: reward 0

    def check_winner(self):                                 # XXX eller OOO på en linje?
        lines = [(0, 1, 2), (3, 4, 5), (6, 7, 8),            # rader
                 (0, 3, 6), (1, 4, 7), (2, 5, 8),            # kolonner
                 (0, 4, 8), (2, 4, 6)]                       # diagonaler
        s = self.state
        return any(s[a] == s[b] == s[c] and s[a] in 'XO' for a, b, c in lines)

    def render(self):                                       # valgfri: tegn brettet
        for row in range(3):
            print(' '.join(self.state[3 * row:3 * row + 3]))
        print()

Legg merke til at reward = 0 for alle trekk som ikke avslutter spillet, og at done = True både ved seier og ved fullt brett. Det er grunnen til at Q-verdiene i tabellen bare sprer seg bakover ett trekk per parti; se 4A · 06.

04 · Agent

Player: tag, Q-tabell og ε-greedy

Notatene · avsnitt 4.4 · s. 59–60 (egenskapene og choose_action); tabellvarianten er forslag

En agent som lærer tre-på-rad må minimum ha tag (X eller O), en Q-tabell (dictionary med state som key) og parametrene \(\alpha\), \(\gamma\) og \(\epsilon\), pluss metoder for å velge action, lære og oppdatere \(\epsilon\).

import random
import numpy as np

class Player:
    def __init__(self, tag, alpha=0.5, gamma=0.9, exp_factor=1.0, exp_min=0.05, epsilon_decay=0.99):
        self.tag = tag                      # 'X' eller 'O'
        self.values = {}                    # Q-tabell: state → {action: Q}, tom i starten
        self.alpha = alpha                  # læringsrate α i (115)
        self.gamma = gamma                  # discount factor γ
        self.exp_factor = exp_factor        # ε, starter høyt
        self.exp_min = exp_min              # gulvet for ε
        self.epsilon_decay = epsilon_decay  # faktor per kall på update_exp_factor

Velge action

Funksjonen for å velge action, slik den står for agenten som bruker et nevralt nettverk:

def choose_action(self, state):
    available_actions = [_i for _i, _s in enumerate(state) if _s.isnumeric()]
    # If only one move available, make that one
    if len(available_actions) == 0:
        return None
    elif len(available_actions) == 1:
        action = available_actions[0]
        return action
    else:
        qvalues = []
        for _action in available_actions:
            potential_state = state[:_action] + self.tag + state[_action+1:]
            qvalues.append(self.model.predict(self.state_to_array(potential_state),
                verbose=0)[0][0])
        max_index = np.argmax(qvalues)
        best_action = available_actions[max_index]
        return best_action

Den gjør fire ting: 1) får oversikt over mulige trekk, de numeriske tegnene i state; ingen ledige gir None, ett ledig returneres direkte. 2) Sjekker om staten finnes i Q-tabellen, og setter den inn med Q-verdi 0 hvis ikke. 3) Trekker et tilfeldig tall i \([0, 1)\); er det mindre enn \(\epsilon\), returneres en tilfeldig action. 4) Ellers returneres actionen med høyest Q-verdi for aktuell state.

Koden over er nettverksvarianten: self.model.predict gir verdien av brettet etter trekket (potential_state, konvertert til tall med state_to_array), og Q-verdien for action \(A\) i state \(S\) er altså verdien av staten trekket fører til. Den viser steg 1 og 4; steg 2 og 3 (oppslag i tabellen og \(\epsilon\)) hører til tabellvarianten:

def choose_action(self, state):
    available_actions = [_i for _i, _s in enumerate(state) if _s.isnumeric()]   # 1) mulige trekk
    if len(available_actions) == 0:
        return None
    elif len(available_actions) == 1:
        return available_actions[0]
    self.values.setdefault(state, {a: 0.0 for a in available_actions})          # 2) ukjent state → Q = 0
    if np.random.rand() < self.exp_factor:                                       # 3) med sannsynlighet ε:
        return random.choice(available_actions)                                 #    tilfeldig action (explore)
    qvalues = self.values[state]                                                 # 4) ellers: høyest Q (exploit)
    return max(available_actions, key=lambda a: qvalues[a])

Det er epsilon greedy i to linjer: steg 3 er utforskingen, steg 4 utnyttingen. Settes exp_factor = 0, forsvinner steg 3 og agenten spiller det samme partiet hver gang.

05 · Læring

learn er Bellman-likningen linje for linje

Notatene · avsnitt 4.5 · s. 60–61 (learn og update_exp_factor); tabellvarianten og replay-bufferet er forslag

Q-verdiene oppdateres etter hvert trekk med likning (115), \(Q^{new} \leftarrow (1-\alpha) Q + \alpha (R_{t+1} + \gamma \max_A Q(S_{t+1}, A))\). I nettverksvarianten:

def learn(self, state, action, reward, new_state, done):
    v_s = self.calc_value(state)[0]
    if done:
        v_s_next = 0
    else:
        v_s_next = self.calc_value(new_state)[0]
    td_target = reward + (0 if done else self.gamma*v_s_next)
    td_delta = td_target - v_s
    new_qvalue = v_s + self.alpha*td_delta
    y_train = new_qvalue
    model_input = self.state_to_array(state).reshape(1,-1)
    self.train_model(model_input, y_train, self.train_steps)
    return

Første linje henter den gamle Q-verdien. Deretter hentes den maksimale fremtidige verdien, med mindre den ikke finnes (spillet er over), da settes den til 0. Så brukes disse to størrelsene og parametrene satt ved start til å beregne den nye Q-verdien, som erstatter den gamle. Funksjonen returnerer ingenting. Læringen skjer for hvert trekk, og funksjonen trenger state, valgt action, ny state og reward for trekket. I tre-på-rad er reward = 0 med mindre spillet er over, og da er maksimal fremtidig verdi 0. Q-læring går ut på å oppdatere Q-verdier gjennom erfaring.

Samme funksjon for tabellagenten, der nøstingen er values[state][action]:

def learn(self, state, action, reward, new_state, done):
    q_old = self.values.setdefault(state, {}).get(action, 0.0)        # Q(S_t, A_t), 0 om ukjent
    if done or not self.values.get(new_state):                        # spillet over, eller ny state ukjent
        max_q_next = 0.0
    else:
        max_q_next = max(self.values[new_state].values())            # max_A Q(S_{t+1}, A)
    td_target = reward + self.gamma * max_q_next
    td_delta = td_target - q_old
    self.values[state][action] = q_old + self.alpha * td_delta        # (115), skrevet rett inn i tabellen

Minke ε

def update_exp_factor(self):
    if self.exp_factor > self.exp_min:
        self.exp_factor *= self.epsilon_decay

Kalles typisk én gang per spill. ε avtar geometrisk til exp_min og blir der (epsilon decay). Har agenten ikke lært noe innen ε når gulvet, hjelper det sjelden å trene videre; endre heller andre deler av koden, for eksempel tapsfunksjonen. Plott på 4A · 05.

Replay buffer (DQN)

Trenes nettverket på trekkene i den rekkefølgen de skjer, overtilpasser det de nyeste erfaringene. I stedet lagres overgangene i en replay buffer, og nettverket trenes på tilfeldige minibatcher fra den (forslag; se 4A · 07):

buffer = []                                                     # liste av (state, action, reward, next_state, done)
buffer.append((state, action, reward, new_state, done))         # etter hvert trekk
if len(buffer) >= 32:
    minibatch = random.sample(buffer, k=32)                     # 32 tilfeldige overganger, uten tilbakelegging
    for s, a, r, s2, d in minibatch:
        agent.learn(s, a, r, s2, d)

Du har en replay-buffer lagret som en liste med transisjoner, se kode over. Hvilken Python-funksjon brukes for å trekke en tilfeldig minibatch?

  1. np.take(buffer, 32)
  2. random.sample(buffer, k=32)
  3. np.take(buffer, 32)
  4. buffer.sort()
Svar fra løsningsforslaget · begrunnelse er forslag (replay buffer er ikke i notatene)

B. random.sample(liste, k) trekker \(k\) ulike elementer tilfeldig, uten tilbakelegging, akkurat det en minibatch skal være. np.take(buffer, 32) (A og C er like) henter elementet på indeks 32, ingenting tilfeldig. buffer.sort() sorterer lista på plass og returnerer None.
