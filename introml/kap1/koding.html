02 · Oppskriften

Hele løypa i ett skjelett

Notatene · avsnitt 1.1–1.2.4 satt sammen

Uansett modell er rekkefølgen den samme: les data, rydd, splitt, skaler, tren, prediker, evaluer, plott. Skjelettet under er det du fyller ut i hver øving. Alt som står med fit skjer på treningsdata alene.

df = pd.read_csv("data.csv")

for kol in KATEGORISKE:                              # 2. enkode strenger til tall

X = df[FEATURES].values
y = df[TARGET].values
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3)   # 3. splitt FØR skalering

scaler = MinMaxScaler().fit(X_train)                 # 4. skaler: fit på trening ...
X_train = scaler.transform(X_train)
X_test  = scaler.transform(X_test)                   #    ... transform på begge

modell = LogisticRegression(learning_rate=0.01, epochs=30)   # 5. egen klasse (04) eller sklearn
modell.fit(X_train, y_train)                         # 6. tren

De to feilene som går igjen

Skalering før splitt (steg 3 og 4 i feil rekkefølge) lekker testdata inn i treningen. Hyperparametre justert på testsettet gjør at du ikke har usette data igjen; bruk et valideringssett (09).

Hva fit, transform og fit_transform gjør

fit(X)
Lærer parametrene fra X: min og maks for MinMaxScaler, snitt og standardavvik for StandardScaler, verdimengden for LabelEncoder. Endrer ikke X.
transform(X)
Bruker de lærte parametrene på X. Kan kalles på hvilket som helst datasett med samme kolonner.
fit_transform(X)
Begge deler i ett kall. Bare på treningsdata (eller på hele kolonner der det ikke lekker informasjon, som LabelEncoder på en kategorisk kolonne).

Plott før modellering

Bar-plott viser middelverdien av target per kategori; histogram viser fordelingen til en feature innad i hver klasse. Antall bins er en vurderingssak: for mange gir hakkete stolper, for få skjuler formen.

Sjekk forståelsen · Lett
Du kjører MinMaxScaler().fit_transform(X) på hele datasettet og splitter etterpå. Hva har gått galt, og hvordan oppdager en sensor det i koden?

04 · Logistisk regresjon fra bunnen

Klassen du skal fylle ut

Notatene · avsnitt 1.2.3 · s. 8–9 (skjelettet og fit/predict); metodekroppene er forslag

Notatene gir klassen med tomme metoder og sier at du skriver kroppene selv. Under er skjelettet slik det står, og deretter et forslag til hver metode, direkte fra formlene på 1A: sigmoid (3), cross entropy (11), gradientene (22) og (25), oppdateringen (13). Behold navnene fit og predict; de er standard i alle biblioteker.

class LogisticRegression:
    def __init__(self, learning_rate=0.1, epochs=1000):
        self.learning_rate = learning_rate
        self.epochs = epochs
        self.weights, self.bias = None, None
        self.losses, self.train_accuracies = [], []

    def sigmoid_function(self, x):
    def _compute_loss(self, y, y_pred):
    def compute_gradients(self, x, y, y_pred):
    def update_parameters(self, grad_w, grad_b):

    def accuracy(true_values, predictions):
        return np.mean(true_values == predictions)
def sigmoid_function(self, x):                       # likning (3)
    return 1 / (1 + np.exp(-x))

def _compute_loss(self, y, y_pred):                  # likning (11), snitt over datapunktene
    eps = 1e-12                                      # unngå log(0)
    y_pred = np.clip(y_pred, eps, 1 - eps)
    return np.mean(-y * np.log(y_pred) - (1 - y) * np.log(1 - y_pred))

def compute_gradients(self, x, y, y_pred):           # likning (22) og (25), snitt over datapunktene
    diff = y_pred - y                                # shape (N,)
    grad_w = np.matmul(x.transpose(), diff) / len(y) # shape (features,): sum_i (y_pred_i - y_i) x_ij
    grad_b = np.mean(diff)
    return grad_w, grad_b

def update_parameters(self, grad_w, grad_b):         # likning (13)
    self.weights = self.weights - self.learning_rate * grad_w
    self.bias    = self.bias    - self.learning_rate * grad_b

Så fit og predict, som notatene gir ferdig:

def fit(self, x, y):
    self.weights = np.zeros(x.shape[1])   # x.shape = (datapunkter, features)
    self.bias = 0

    for _ in range(self.epochs):          # én epoke = gradient descent på alle treningsdata
        lin_model = np.matmul(self.weights, x.transpose()) + self.bias
        y_pred = self._sigmoid(lin_model)
        grad_w, grad_b = self.compute_gradients(x, y, y_pred)
        self.update_parameters(grad_w, grad_b)

        loss = self._compute_loss(y, y_pred)
        pred_to_class = [1 if _y > 0.5 else 0 for _y in y_pred]
        self.train_accuracies.append(accuracy(y, pred_to_class))
        self.losses.append(loss)

def predict(self, x):
    lin_model = np.matmul(x, self.weights) + self.bias
    y_pred = self._sigmoid(lin_model)
    return [1 if _y > 0.5 else 0 for _y in y_pred]
Shapes å holde styr på

x er (N, d), weights er (d,). np.matmul(weights, x.T) og np.matmul(x, weights) gir begge (N,): ett tall \(z\) per datapunkt. y_pred - y er (N,), og x.T @ (y_pred - y) er (d,): én gradientkomponent per vekt. Får du en shape-feil, er det nesten alltid her.

Sjekk forståelsen · Middels
Hvorfor deler compute_gradients på len(y), når likning (22) ikke har noen \(1/N\)?
Likning (22) er gradienten for ett datapunkt. Optimeringsproblemet (12) minimerer gjennomsnittet over alle \(N\) punkter, så gradienten av det er gjennomsnittet av enkeltgradientene. Uten \(1/N\) skalerer steget med datasettets størrelse, og læringsraten måtte justeres for hvert datasett.
05 · Evaluering

Confusion matrix, metrikker og ROC for hånd

Notatene · avsnitt 1.2.4–1.2.5 · s. 9–12 (tabell 4, figur 5–7); koden er forslag

Notatene definerer confusion matrix og metrikkene i tabell 4, men gir ikke kode. Alt kan regnes med fire tellinger, og ROC-kurven er de samme fire tellingene gjentatt for mange terskler.

def confusion(y_true, y_pred):
    TP = np.sum((y_true == 1) & (y_pred == 1))
    TN = np.sum((y_true == 0) & (y_pred == 0))
    FP = np.sum((y_true == 0) & (y_pred == 1))     # falsk alarm
    FN = np.sum((y_true == 1) & (y_pred == 0))     # missed case
    return TP, TN, FP, FN

def metrics(TP, TN, FP, FN):                        # tabell 4 + (26), (27)
    return {
        "accuracy":    (TP + TN) / (TP + TN + FP + FN),
        "TPR/recall":  TP / (TP + FN),
        "TNR":         TN / (TN + FP),
        "FPR":         FP / (FP + TN),
        "precision":   TP / (TP + FP),
    }

def roc_curve(y_true, y_prob):                      # figur 6: sveip terskelen fra 1 til 0
    points = []
    for t in np.linspace(1, 0, 101):
        y_pred = (y_prob > t).astype(int)           # samme regel som i predict, med terskel t
        TP, TN, FP, FN = confusion(y_true, y_pred)
        points.append((FP / (FP + TN), TP / (TP + FN)))   # (FPR, TPR)
    return points                                   # starter i (0,0), ender i (1,1)

def auc(points):                                    # arealet under kurven, trapesmetoden
    xs, ys = zip(*points)
    return np.trapz(ys, xs)

Precision–recall-kurven (figur 7) er samme sveip med (recall, precision) som punkter. Merk at y_prob er sigmoid-outputen før terskelen; predict i 04 returnerer klasser, så du trenger en predict_proba som returnerer y_pred uten listeforståelsen.

Deling på null

Ved terskel 1 er ingen predikert positive, så \(TP + FP = 0\) og precision er udefinert. Sjekk nevneren, eller start sveipet litt under 1. sklearn gjør det samme og gir en advarsel.

06 · Ubalanserte data

Terskel, resampling og vektet tap

Notatene · avsnitt 1.2.10 · s. 16–17; resampling-koden er forslag

Tre grep, i økende inngripen: flytt terskelen (endrer ikke modellen), endre dataene (undersampling / oversampling), eller endre tapsfunksjonen (vektet cross entropy).

y_pred = [1 if _y > 0.5 else 0 for _y in y_pred]   # bytt 0.5 med terskel valgt fra precision-recall-plottet
def undersample(X, y, minority=1):
    idx_min = np.where(y == minority)[0]
    idx_maj = np.where(y != minority)[0]
    keep = np.random.choice(idx_maj, size=len(idx_min), replace=False)   # like mange fra majoriteten
    idx = np.concatenate([idx_min, keep])
    return X[idx], y[idx]                            # totalt 2 * n_minoritet punkter

def oversample(X, y, minority=1):
    idx_min = np.where(y == minority)[0]
    idx_maj = np.where(y != minority)[0]
    extra = np.random.choice(idx_min, size=len(idx_maj) - len(idx_min), replace=True)   # duplikater
    idx = np.concatenate([idx_maj, idx_min, extra])
    return X[idx], y[idx]                            # totalt 2 * n_majoritet punkter

Vektet tap er én linje endret i _compute_loss (likning 43), og gradientene får samme vekter per datapunkt:

def _compute_loss(self, y, y_pred, w0=1.0, w1=1.0):
    return np.mean(-w1 * y * np.log(y_pred) - w0 * (1 - y) * np.log(1 - y_pred))

def compute_gradients(self, x, y, y_pred, w0=1.0, w1=1.0):
    weights_per_point = np.where(y == 1, w1, w0)   # w1 der y = 1, w0 der y = 0
    diff = weights_per_point * (y_pred - y)
    return np.matmul(x.transpose(), diff) / len(y), np.mean(diff)

07 · Naïv Bayes i kode

Tellinger blir sannsynligheter

Notatene · avsnitt 1.2.7–1.2.8 · s. 13–15 (crosstab-koden); klassifikatoren er forslag

Med kategoriske features er naïv Bayes bare tellinger: prior \(p(C_k)\) er andelen per klasse, og hver \(p(x_i \mid C_k)\) er en normalisert krysstabell. Kontinuerlige features (Age) deles først i bins med np.histogram.

def fit_naive_bayes(df, features, target):
    prior = df[target].value_counts(normalize=True)           # p(C_k)
    cond = {f: pd.crosstab(df[target], df[f], normalize="index") for f in features}   # p(x_f | C_k)
    return prior, cond

def predict_naive_bayes(prior, cond, x):                      # likning (38)
    scores = {}
    for k in prior.index:
        s = prior[k]
        for f, v in x.items():
            s *= cond[f].loc[k, v]                            # produktet over features
        scores[k] = s
    return max(scores, key=scores.get)                        # argmax_k; ikke kalibrert sannsynlighet

08 · Beslutningstrær

Gini, entropi og sklearn-treet

Notatene · avsnitt 1.3.2–1.3.4 · s. 18–20

I dette kurset bygger du ikke trær selv, men du bør kunne pseudokoden, og du bruker DecisionTreeClassifier i øvingene. Splitt-kriteriene er to små funksjoner; bruk dem til å sjekke regnestykkene fra 1B.

def gini(counts):                                  # likning (44); counts = antall per klasse i noden
    p = np.array(counts) / np.sum(counts)
    return 1 - np.sum(p ** 2)

def entropy(counts):                               # likning (46)
    p = np.array(counts) / np.sum(counts)
    p = p[p > 0]                                   # 0 log 0 = 0
    return -np.sum(p * np.log2(p))

def split_score(left, right, f=gini):              # likning (45) / (48): vektet snitt over barna
    n_l, n_r = np.sum(left), np.sum(right)
    return (n_l * f(left) + n_r * f(right)) / (n_l + n_r)

def information_gain(parent, left, right):         # likning (49)
    return entropy(parent) - split_score(left, right, entropy)

# tabell 6: gini([0, 10]) = 0.0, gini([3, 7]) = 0.42, gini([5, 5]) = 0.5
# oppgaven p=9, n=5: entropy([9, 5]) = 0.94, split_score([4, 5], [5, 0], entropy) = 0.64
def build_decision_tree(data, features, depth):
    if (all data in same class):
        return class label
    elif (no features left to test) or (depth >= max_depth):
        return 1 if p/(p+n) > n/(p+n) else 0
    elif (no data left to test):
        return (dominant class in parent node)
    else:
        choose best_feature f for split               # lavest gini / størst informasjonsgevinst
        partition data based on f
        for each data partition:
            build_decision_tree(data partition, features - best_feature, depth+1)

09 · Regresjon

Gjenbruk, polynomer, validering og k-fold

Notatene · avsnitt 1.4.1–1.4.6 · s. 20–32

Lineær regresjon er logistisk regresjon uten sigmoid og med MSE. Tre metoder endres; resten av klassen fra 04 beholdes. Gradientene er (55) og (56), oppdateringen (57).

class LinearRegression(LogisticRegression):        # arv alt, bytt tre metoder
    def _linear(self, x):
        return np.matmul(x, self.weights) + self.bias   # ingen sigmoid

    def _compute_loss(self, y, y_pred):            # likning (52)
        return np.mean((y - y_pred) ** 2) / 2

    def compute_gradients(self, x, y, y_pred):     # likning (55), (56): samme form som logistisk!
        diff = y_pred - y
        return np.matmul(x.transpose(), diff) / len(y), np.mean(diff)

    def predict(self, x):
        return self._linear(x)                     # et tall, ikke en klasse

    val_loss = mean_squared_error(y_val, y_val_pred)
    val_losses.append(val_loss)
# early stopping: stopp når val_loss ikke har bedret seg på 'patience' epoker
best, since_best = np.inf, 0
for epoch in range(n_epochs):
    model.partial_fit(X_train, y_train)
    val_loss = mean_squared_error(y_val, model.predict(X_val))
    if val_loss < best - tol:
        best, since_best = val_loss, 0
    else:
        since_best += 1
        if since_best >= patience:
            break

def k_fold(X, y, k, make_model):
    idx = np.random.permutation(len(y))
    folds = np.array_split(idx, k)                 # k ikke-overlappende deler
    scores = []
    for i in range(k):
        test_idx  = folds[i]
        train_idx = np.concatenate([folds[j] for j in range(k) if j != i])
        model = make_model().fit(X[train_idx], y[train_idx])
        scores.append(mean_squared_error(y[test_idx], model.predict(X[test_idx])))
    return np.mean(scores)                         # LOOCV = k_fold med k = len(y)

Bootstrap, bagging og boosting i kode

Notatene · avsnitt 1.5 · s. 32–34 (læringsregelen for gradient boosting); resten er forslag

Notatene gir bare læringsregelen for gradient boosting og navnene på bibliotekene. I øvingene bruker du sklearn; pseudokoden under viser hva som skjer inni.

def bootstrap_sample(X, y):
    idx = np.random.choice(len(y), size=len(y), replace=True)   # MED tilbakelegging
    return X[idx], y[idx]

def bagging_fit(X, y, n_models, make_model):
    return [make_model().fit(*bootstrap_sample(X, y)) for _ in range(n_models)]

def bagging_predict(models, X, task="classification"):
    preds = np.array([m.predict(X) for m in models])          # (n_models, N)
    if task == "regression":
        return preds.mean(axis=0)                             # gjennomsnitt
    return np.apply_along_axis(lambda col: np.bincount(col).argmax(), 0, preds)   # flertall
def gradient_boosting_fit(X, y, n_trees, learning_rate, max_depth=1):
    F0 = np.mean(y)                                # start: gjennomsnittet
    trees = []
    F = np.full(len(y), F0)
    for _ in range(n_trees):
        residual = y - F                           # pseudo-residualer = -gradient av 1/2 (y - F)^2
        t = tree.DecisionTreeRegressor(max_depth=max_depth).fit(X, residual)
        trees.append(t)
        F = F + learning_rate * t.predict(X)       # new_ensemble = previous_ensemble - lr * (-residualtre)
    return F0, trees

def gradient_boosting_predict(F0, trees, learning_rate, X):
    return F0 + sum(learning_rate * t.predict(X) for t in trees)

Spørsmål 2 · Middels
Hva er forskjellen på np.random.choice(n, n, replace=True) og np.random.permutation(n), og hvilken hører til bagging og hvilken til k-fold?
choice med replace=True trekker \(n\) indekser med tilbakelegging: duplikater og hull, det er en bootstrap-trekning og hører til bagging. permutation stokker alle \(n\) indeksene én gang uten gjentak; delt i \(k\) biter gir det ikke-overlappende folds til kryssvalidering. Det er nøyaktig forskjellen eksamen 2024 spm. 18 spør om.
Spørsmål 3 · Vanskelig
I gradient_boosting_fit tilpasses treet til residual = y - F og legges til med pluss. Notatene skriver new_ensemble = previous_ensemble - learning_rate * new_tree. Hvorfor er det samme algoritme?
Notatene lar treet tilpasse gradienten \(-(y - F)\), altså den negative residualen, og trekker fra. Koden lar treet tilpasse residualen \(y - F\) og legger til. Siden \(F - \eta \cdot (-(y - F)) = F + \eta (y - F)\), er stegene identiske; det er bare et fortegn flyttet fra treet til oppdateringen. Begge er gradient descent på \(\tfrac12(y - F)^2\) i rommet av trær.
