01 · Prosedyren

Én algoritme, mange strategier

Slides forelesning 2 · 71–98 og 202 · Boka kap. 3.3.1 · s. 91
Deltema 2.2 · prio 1

Du står i startnoden. (1) Er dette målet? (2) Hvis ikke: ekspander noden, dvs. generer etterfølgerne. (3) Legg dem i frontier. (4) Velg neste node fra frontier etter en evalueringsfunksjon \(f(n)\). Gjenta. Når måltesten gjøres, avhenger av algoritmen.

Alle strategiene i kurset unntatt BFS er best-first search: frontier er en prioritetskø ordnet etter \(f\), og bare \(f\) skiller dem.

function BEST-FIRST-SEARCH(problem, f) returns a solution node or failure
  node ← NODE(STATE=problem.INITIAL)
  frontier ← a priority queue ordered by f, with node as an element
  reached ← a lookup table, with one entry with key problem.INITIAL and value node
  while not IS-EMPTY(frontier) do
    node ← POP(frontier)
    if problem.IS-GOAL(node.STATE) then return node        ← sen måltest
    for each child in EXPAND(problem, node) do
      s ← child.STATE
      if s is not in reached or child.PATH-COST < reached[s].PATH-COST then
        reached[s] ← child
        add child to frontier
  return failure

function EXPAND(problem, node) yields nodes
  s ← node.STATE
  for each action in problem.ACTIONS(s) do
    s' ← problem.RESULT(s, action)
    cost ← node.PATH-COST + problem.ACTION-COST(s, action, s')
    yield NODE(STATE=s', PARENT=node, ACTION=action, PATH-COST=cost)

Depth-first search\(-\text{depth}(n)\)LIFO-kø (stakk): dypeste først
Uniform-cost search (Dijkstra)\(g(n)\)billigste stikostnad først

Algoritmene vurderes på fire mål: fullstendighet (finner den alltid en løsning om det finnes en?), kostnadsoptimalitet (finner den billigste?), tidskompleksitet og plasskompleksitet.

Nøkkelpoeng

Etter at Arad er ekspandert ligger Sibiu, Timisoara, Zerind i frontier (lagt til i den rekkefølgen). FIFO popper Sibiu (først inn), LIFO popper Zerind (sist inn), prioritetskø etter \(g\) popper også Zerind (75 mi er billigst), men av en helt annen grunn.

02 · Fallgruver

Tre detaljer som endrer svaret

Slides forelesning 2 · 112–115 og 201 · Forelesning 3 · 5–10 · Assignment-forelesning 1 · 2–7

Assignment-forelesningen sier det rett ut: små detaljer gir store forskjeller, og «A*» på nettet er sjelden kursets A*. Har du tatt TDT4120, er dette stedet du lettest går i fella.

  1. Graph search eller tree-like search? Graph search bruker reached og legger ikke inn en tilstand på nytt med dårligere kostnad (redundante stier). Tree-like search er samme pseudokode uten reached-testen: alle barn legges i frontier, også løkker. Står det «tree-like» i oppgaven, er det dette.
  2. Når sjekkes målet? BFS har tidlig måltest: målet sjekkes når en node genereres, og søket stopper før målet legges i frontier. Alle best-first-variantene (DFS, UCS, greedy, A*) har sen måltest: målet sjekkes når noden poppes for ekspansjon.
  3. Uavgjort? Behandle etterfølgere i alfabetisk rekkefølge, og ved likt \(f\) i prioritetskøen: velg alfabetisk (eller «venstre til høyre» om oppgaven sier det).

Svarformatet fra assignment-forelesningen og eksamen. Målet står i parentes fordi det ikke ekspanderes, bare oppdages:

Order of expansion: S, A, B, (G)
Found path: S B G
Path cost: 4
Vanlig feil

Å stoppe UCS når målet først dukker opp i frontier. UCS (og A*) stopper først når målet poppes; en billigere vei kan bli funnet i mellomtiden. Og motsatt: å fortsette BFS etter at målet er generert.

03 · BFS

Bredde først, mål tidlig

Slides forelesning 2 · 116–129 · Boka kap. 3.4.1 · s. 95

Breadth-first search ekspanderer de eldste nodene først: frontier er en FIFO-kø. Kursets offisielle versjon er bokas s. 95:

function BREADTH-FIRST-SEARCH(problem) returns a solution node or failure
  node ← NODE(problem.INITIAL)
  if problem.IS-GOAL(node.STATE) then return node
  frontier ← a FIFO queue, with node as an element
  reached ← {problem.INITIAL}
  while not IS-EMPTY(frontier) do
    node ← POP(frontier)
    for each child in EXPAND(problem, node) do
      s ← child.STATE
      if problem.IS-GOAL(s) then return child              ← tidlig måltest
      if s is not in reached then
        add s to reached
        add child to frontier
  return failure

Grafen under er slidenes gjennomgående eksempel for BFS, DFS og UCS (start A, mål G).

Løsningen hentes ved å følge PARENT-pekerne bakover fra G: A → B → E → G, kostnad \(5+3+17 = 25\). BFS er fullstendig i endelige rom, men ikke kostnadsoptimal med ulike kostnader; tid og plass \(O(b^d)\), der \(b\) er forgreiningsfaktoren og \(d\) dybden til den grunneste løsningen.

04 · DFS

Dybde først

Slides forelesning 2 · 130–142

Depth-first search ekspanderer den nyeste (dypeste) noden først: best-first med \(f(n) = -\text{depth}(n)\), altså en stakk. Etterfølgerne legges på stakken i omvendt rekkefølge, slik at den alfabetisk første havner øverst.

DFS på slidegrafen (slides 130–137); toppen av stakken står først
EkspandererFrontier etterpå
A⟨B, C⟩
B⟨D, E, C⟩
D⟨F, E, C⟩
F⟨G, E, C⟩
G poppes: målE og C ble aldri besøkt

Sti A → B → D → F → G, kostnad 23. DFS var heldig her. Den er ikke fullstendig (feiler i uendelig dype rom og i løkker, fordi den vanligvis kjøres som tree-like search) og ikke kostnadsoptimal. Til gjengjeld er plassbruken lineær: tid \(O(b^m)\), plass \(O(bm)\), der \(m\) er maksimal dybde.

05 · DLS og IDS

Dybdegrense og iterativ fordypning

Slides forelesning 2 · 143–145 · pseudokoden: Boka kap. 3.4.4 (ikke i slidene)

Depth-limited search er DFS med en grense \(\ell\): noder på dybde \(\ell\) behandles som om de ikke har etterfølgere. Iterative deepening search prøver \(\ell = 0, 1, 2, \dots\) til den finner en løsning. Begge kjøres som tree-like search. Resultatet er en løsning, failure, eller cutoff: grensen ble nådd, så det kan finnes en løsning dypere.

function ITERATIVE-DEEPENING-SEARCH(problem) returns a solution node or failure
  for depth = 0 to ∞ do
    result ← DEPTH-LIMITED-SEARCH(problem, depth)
    if result ≠ cutoff then return result

function DEPTH-LIMITED-SEARCH(problem, ℓ) returns a node or failure or cutoff
  frontier ← a LIFO queue (stack) with NODE(problem.INITIAL) as an element
  result ← failure
  while not IS-EMPTY(frontier) do
    node ← POP(frontier)
    if problem.IS-GOAL(node.STATE) then return node
    if DEPTH(node) > ℓ then result ← cutoff
    else if not IS-CYCLE(node) do
      for each child in EXPAND(problem, node) do add child to frontier
  return result

IDS er fullstendig når rommet er endelig, kostnadsoptimal bare når alle kostnader er like (som BFS), med tid \(O(b^d)\) og plass \(O(bd)\) (som DFS). Slidene: «slightly better than both DFS and BFS».

Hvor går grensen?

Slideteksten sier at noder på dybde \(\ell\) ikke får etterfølgere. Bokas pseudokode (og løsningsforslaget under) kutter først noder med dybde \(\gt \ell\), så nodene på dybde \(\ell\) blir ekspandert. Skriv hvilken konvensjon du bruker på eksamen.

Eksamen Ord. 2022 · oppg. 3.2ulv, geit og kål

Apply iterative deepening search with depth limit of 3. Enumerate nodes in the order they are expanded. (Tilstandsgrafen og notasjonen står i 2A: 1 = vare på startsiden, i/o = bondens side.)

Svar fra løsningsforslaget

Løsningsforslaget velger alltid det minste tallet først og går videre til neste dybde ved første cutoff:

depth=0  111-i (barn 011-o, 101-o, 110-o, 111-o) → 011-o på nivå 1: cutoff
depth=1  111-i → 011-o (ingen barn) → 101-o (barn 101-i) → 101-i på nivå 2: cutoff
depth=2  111-i → 011-o → 101-o → 101-i (barn 001-o, 100-o) → 001-o på nivå 3: cutoff
depth=3  111-i → 011-o → 101-o → 101-i → 001-o (barn 001-i, 011-i) → 001-i på nivå 4: cutoff

Barn som er forfedre på stien (f.eks. 111-i under 101-o) genereres ikke. 011-o, 110-o og 111-o er tilstander der noe spises, så de har ingen barn.

Forslag til svar · ikke fasit fra løsningsforslaget

Bokas DLS stopper ikke ved første cutoff; den popper resten av stakken også. Med samme konvensjoner (minste først, dybde \(\gt \ell\) gir cutoff, forfedre genereres ikke) blir den fullstendige ekspansjonsrekkefølgen:

06 · UCS

Billigste sti først

Slides forelesning 2 · 146–159

Uniform-cost search (Dijkstra) ekspanderer alltid noden med lavest stikostnad: \(f(n) = g(n)\). Måltesten er sen: G kan ligge i frontier lenge før den poppes, og en billigere vei kan erstatte den.

EkspandererFrontier etterpåKommentar
A (0){B:5, C:7}
B (5){C:7, E:8, D:13}
C (7){E:8, D:13}blindvei
E (8){D:13, G:25}G nådd, men ikke billigst: ikke stopp
D (13){F:17, G:25}
F (17){G:23}billigere vei til G: 23 < 25 erstatter
G (23) poppes–mål

UCS er kostnadsoptimal (finner 23, mens BFS fant A → B → E → G til 25) og fullstendig så lenge alle kostnader er \(\ge \epsilon \gt 0\). Tid og plass er \(O(b^{1+\lfloor C^*/\epsilon \rfloor})\), der \(C^*\) er kostnaden til den optimale løsningen.

Sjekk forståelsen · Middels
Hvorfor er IDS ofte å foretrekke framfor BFS når tilstandsrommet er stort og løsningsdybden ukjent?
IDS har samme garantier som BFS (fullstendig, optimal ved like kostnader) og samme tid \(O(b^d)\), men bare lineær plass \(O(bd)\) som DFS. BFS må lagre hele frontier, \(O(b^d)\). At de øverste nivåene genereres flere ganger koster lite, fordi det nederste nivået dominerer.

Spørsmål 1 · Middels
Kjør BFS (graph search) på assignment-eksempelgrafen: kanter A–B 3, A–C 2, C–D 3, D–E 3, B–E 4 (urettet), start A, mål E.
Ekspander A: genererer B, C. Ekspander B: genererer A (allerede i reached) og E, som er målet. Order of expansion: A, B, (E) · Path: A B E · Cost: 3 + 4 = 7. Samme som på assignment-slidene.
Spørsmål 2 · Middels
UCS på samme graf. Hvorfor ekspanderes D før målet poppes?
Pop A: C:2, B:3. Pop C: D:5 (A:4 avvises). Pop B: E:7. Pop D (5 < 7): E via D koster 8 > 7, avvises. Pop E (7): mål. Order: A, C, B, D, (E), sti A B E, kostnad 7. D ekspanderes fordi \(g(D) = 5 \lt g(E) = 7\), og UCS stopper først når målet poppes.
Spørsmål 3 · Vanskelig
Ville BFS gitt et annet svar på eksamensgrafen om den hadde sen måltest?
Ja. Med sen måltest legges G i frontier etter B: ⟨A, C, G⟩. Så ekspanderes A (løkke) og C, og G poppes: S, A, B, A, C, (G). Stien er fortsatt S B G (17), men ekspansjonsrekkefølgen blir feil. Det er nettopp denne forskjellen løsningsforslaget sier mange bommet på.
