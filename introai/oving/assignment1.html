01 · Hva du skal gjøre

Oppgaven og algoritmevarianten

Assignment-forelesning 1 · slides 2–10 · bygger på forelesning 2–3 og boka kap. 3 · pseudokode: Boka (4. utg., Global) s. 91 og 95

Grafen er et kart over Doom-nivået Phobos Anomaly. A er start, F er mål, og tallet i den grå sirkelen ved hver node er heuristikkverdien. Å krysse en linje koster 1, trapp koster 1 ekstra og heis 2 ekstra (A til G koster 1 + 1 + 2 = 4). Oppgaven har tre deler:

  1. Skriv opp kostnaden for alle kanter, f.eks. (A, G) = 4.
  2. Løs for hånd med BFS, DFS, UCS (Dijkstra), greedy best-first (GBFS) og A*. Oppgi ekspansjonsrekkefølge, funnet sti og stikostnad, på formen «Order of expansion: S, A, B, (G)». Målnoden står i parentes fordi den oppdages, ikke ekspanderes.
  3. Avgjør om heuristikken er admissibel og konsistent. En bonusoppgave er frivillig.
Hvilken variant som gjelder
  • BFS: BREADTH-FIRST-SEARCH. Den sjekker mål med en gang en node genereres, ikke når den tas ut av køen.
  • Alle andre: best-first search med riktig \(f\): UCS \(f = g\), GBFS \(f = h\), A* \(f = g + h\). Her sjekkes mål når noden tas ut (pop). For DFS brukes \(f = -\text{dybde}\) (egen tolkning; gir svaret i eksempelet under).
  • Rekkefølge: naboer behandles alfabetisk. Er \(f\) likt, velg alfabetisk.
  • Grafsøk: begge versjonene husker besøkte tilstander i reached. Nettkilder om «A*» bruker ofte en annen variant.
function BREADTH-FIRST-SEARCH(problem) returns a solution node or failure
  node ← NODE(problem.INITIAL)
  if problem.IS-GOAL(node.STATE) then return node
  frontier ← a FIFO queue, with node as an element
  reached ← {problem.INITIAL}
  while not IS-EMPTY(frontier) do
    node ← POP(frontier)
    for each child in EXPAND(problem, node) do
      s ← child.STATE
      if problem.IS-GOAL(s) then return child        ← målsjekk ved generering
      if s is not in reached then
        add s to reached
        add child to frontier
  return failure

function BEST-FIRST-SEARCH(problem, f) returns a solution node or failure
  node ← NODE(STATE=problem.INITIAL)
  frontier ← a priority queue ordered by f, with node as an element
  reached ← a lookup table, with one entry with key problem.INITIAL and value node
  while not IS-EMPTY(frontier) do
    node ← POP(frontier)
    if problem.IS-GOAL(node.STATE) then return node  ← målsjekk ved pop
    for each child in EXPAND(problem, node) do
      s ← child.STATE
      if s is not in reached or child.PATH-COST < reached[s].PATH-COST then
        reached[s] ← child
        add child to frontier
  return failure

Oppgave fra assignment-forelesningenslide 11

Kjør BFS (s. 95) fra A til E. Gi ekspansjonsrekkefølge, funnet sti og kostnad.

Svar fra assignment-forelesningen

Order of expansion: A, B, (E). Found path: A, B, E. Path cost: 7.

Mellomregning: A er ikke mål. Ekspander A: barn B (ikke mål, legg i kø), C (ikke mål, legg i kø). Kø: [B, C]. Pop B, ekspander: A er i reached; E genereres og er mål, returner med én gang. C blir aldri ekspandert. Kostnad 3 + 4 = 7.

Oppgave fra assignment-forelesningenslide 12

Kjør DFS (best-first, s. 91) fra A til E.

Svar fra assignment-forelesningen

Order of expansion: A, B, (E). Found path: A, B, E. Path cost: 7.

Mellomregning (med \(f = -\text{dybde}\)): pop A, legg til B og C (dybde 1). Likt, alfabetisk: pop B, ikke mål; legg til E (dybde 2). Dypest er E: pop E, mål. Kostnad 7.

Oppgave fra assignment-forelesningenslide 13

Kjør UCS (Dijkstra) fra A til E.

Svar fra assignment-forelesningen

Order of expansion: A, C, B, D, (E). Found path: A, B, E. Path cost: 7.

Mellomregning (\(f = g\)): pop A(0) → B(3), C(2). Pop C(2) → A(4) forkastes (4 er ikke mindre enn 0), D(5). Pop B(3) → E(7). Frontier: D(5), E(7). Pop D(5) → E(8) forkastes siden 8 ≥ 7. Pop E(7): mål.

Oppgave fra assignment-forelesningenslide 14

Kjør greedy best-first search fra A til E.

Svar fra assignment-forelesningen

Order of expansion: A, B, (E). Found path: A, B, E. Path cost: 7.

Mellomregning (\(f = h\)): pop A → B(h = 3), C(h = 7). Pop B → E(h = 5). Frontier: E(5), C(7). Pop E: mål.

Oppgave fra assignment-forelesningenslide 15

Kjør A* fra A til E.

Svar fra assignment-forelesningen

Order of expansion: A, B, C, D, (E). Found path: A, B, E. Path cost: 7.

Mellomregning (\(f = g + h\)): pop A → B: 3 + 3 = 6, C: 2 + 7 = 9. Pop B(6) → E: 7 + 5 = 12. Pop C(9) → D: 5 + 2 = 7. Pop D(7) → E med g = 8 forkastes (8 ≥ 7). Pop E(12): mål. Den høye h(E) = 5 og h(C) = 7 gjør at A* ekspanderer C og D før målet.

Oppgave fra assignment-forelesningenslides 17–18

Er heuristikken admissibel? (Admissibel: overestimerer aldri kostnaden fra en node til målet.)

Svar fra assignment-forelesningen

Nei: (D, E) = 3 mens h(E) = 5.

Full sjekk, \(h(n) \le h^*(n)\) for alle noder: \(h^*(E) = 0\), men \(h(E) = 5\) ✗. \(h^*(D) = 3 \ge 2\) ✓. \(h^*(B) = 4 \ge 3\) ✓. \(h^*(C) = \min(3+3,\ 2+3+4) = 6\), men \(h(C) = 7\) ✗. Det holder med én node som overestimerer.

Oppgave fra assignment-forelesningenslides 17–18

Er heuristikken konsistent? (Konsistent: \(h(n) \le c(n, a, n') + h(n')\) for alle noder \(n\) og etterfølgere \(n'\).)

Svar fra assignment-forelesningen

Nei, fordi alle konsistente heuristikker er admissible, og denne er ikke admissibel.

Merk: den andre begrunnelsen i den opprinnelige løsningen, \(h(D) \le c(D, a, E) + h(E)\) som gir \(2 \le 3 + 5\), er ingen motsigelse; \(2 \le 8\) er sant. Sjekk heller hver kant i begge retninger. Kanten C → D bryter: \(h(C) = 7 \gt 3 + h(D) = 5\). Resten holder, f.eks. E → D: \(5 \le 3 + 2\) og B → E: \(3 \le 4 + 5\).

Sjekk forståelsen · Middels
Hva blir ekspansjonsrekkefølgen for BFS hvis målsjekken flyttes til pop, som i best-first?
A, B, C, (E). E legges i køen når B ekspanderes, men C ligger foran i FIFO-køen og ekspanderes først. Én ekstra ekspansjon; det er nøyaktig denne forskjellen som er den største «gotcha».
03 · Vanlige feil

Hvor poengene forsvinner

Assignment-forelesning 1 · slides 3–7, 18 · pluss egne erfaringspunkter
Vanlige feil
  • Målsjekk på feil sted. BFS sjekker ved generering, alle andre ved pop. Feil sted gir en ekstra (eller manglende) ekspansjon.
  • Glemmer tie-break. Alfabetisk både for rekkefølgen barn genereres i og ved lik \(f\). Står det noe annet i eksamensoppgaven (f.eks. venstre mot høyre), gjelder det.
  • Tar med målet som ekspandert. Skriv målet i parentes: det er oppdaget, ikke ekspandert.
  • Glemmer reached-testen i best-first. En ny sti til en kjent node legges bare i frontier hvis den er billigere.
  • Blander tree search og graph search. Eksamen kan be om «tree-like search» (ingen reached); da kan noder ekspanderes flere ganger.
  • Sjekker konsistens bare én vei. Kantene er urettede, så ulikheten må holde i begge retninger. Og husk at \(h(\text{mål})\) må være 0 for admissibilitet.
  • Glemmer trapp og heis i Doom-grafen. En kant med heis koster 1 + 2 = 3, ikke 1.
